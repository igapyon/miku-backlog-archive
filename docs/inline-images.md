# 本文中の画像と外部リンクの扱い

初期版では、指定プロジェクトに属する課題・Wiki の添付ファイルとして取得済みの画像だけを、本文からローカル参照します。対象外の URL をたどって画像を取得することはしません。

収集処理は、課題・Wiki 添付ファイルのメタデータと本体を保存します。Wiki 本文の対応記法が `get_wiki` の添付情報に見つからない場合だけ、`get_wiki_attachments` で添付一覧を追加照会します。これにより、一覧取得 API にも載っていない添付や削除済み添付が復元されるわけではありません。取得済みの画像は添付一覧でローカルプレビューし、本文中の対応する添付記法もローカル画像へ変換します。添付と照合できない記法は安全なプレーンテキストとして表示し、`http:`、`https:`、`mailto:` の通常リンクだけを有効化します。

同じ課題または Wiki に保存済みの添付に限り、Backlog 記法の `#image(id またはファイル名)`、`#thumbnail(id またはファイル名)`、Wiki の `#attach(ファイル名:id)`、および課題添付画像の `![代替文][ファイル名]` をローカル資産へ変換します。Nulab のヘルプが示す Wiki 添付画像記法は `#image(ID)`、Markdown 画像記法は `![Alt](URL)` です（[Backlog 記法](https://support-ja.backlog.com/hc/ja/articles/360035641594-%E3%83%86%E3%82%AD%E3%82%B9%E3%83%88%E6%95%B4%E5%BD%A2%E3%81%AE%E3%83%AB%E3%83%BC%E3%83%AB-Backlog%E8%A8%98%E6%B3%95)、[Markdown 記法](https://support-ja.backlog.com/hc/ja/articles/360036145833-%E3%83%86%E3%82%AD%E3%82%B9%E3%83%88%E6%95%B4%E5%BD%A2%E3%81%AE%E3%83%AB%E3%83%BC%E3%83%AB-Markdown-%E8%A8%98%E6%B3%95)）。`![Alt][label]` は参照スタイル Markdown の形ですが、対応する `[label]: URL` 定義がなければ画像のリンク先を特定できません。archive は定義先の外部 URL を取得しません。ID・名前が一致しない記法、通常の Markdown 画像 URL、外部画像の URL は文字列のまま残し、`img` として自動読込しません。

本文表示は見出し・リスト・引用・コードフェンス、通常の URL を使うリンクの最小的な Markdown 形式にも対応します。コードフェンス内では添付記法、課題リンク、外部リンクを変換せず、そのまま安全に表示します。

取得済みの課題キー（たとえば `DEMO-1`）は、本文・コメント・Wiki 本文では同じアーカイブ内の課題詳細 HTML への相対リンクに変換します。さらに、取得元と同じドメインの課題 URL、`pageId` が取得済み Wiki を指す URL、保存済み共有ファイルのダウンロード URL は、条件を満たす場合だけローカル資産へ変換します。変換規則と対象外の URL は [本文中の内部リンク](internal-links.md) を参照してください。

## 外部リンクの保持

本文中の通常の外部リンクは、取得対象外であっても元のリンク先を保存し、生成 HTML では利用者がクリックできるリンクとして残します。アーカイブ作成時や `file://` での通常の閲覧時に、リンク先へ自動アクセスすることはありません。

外部画像は自動読込を避けるため、`<img>` 要素としては生成せず、元の画像 URL への通常リンクとして表示します。これにより、リンク先を失わずに、ページを開いただけで外部通信が発生することも防ぎます。

`http:`、`https:`、`mailto:` 以外のスキームは初期版でリンクとして有効化しません。特に `javascript:`、`vbscript:`、`data:` は文字列として扱います。URL に認証情報が含まれる場合は、ユーザー情報部や API キーなどの値を伏せてから保存・表示します。通常のクエリやフラグメントは、認証情報を含まない限り保持します。

## ローカル化する画像

本文中の画像参照は、次のすべてを満たす場合にローカル化します。

1. 課題本文・コメント・Wiki 本文から見つかった参照であること
2. 指定プロジェクトから取得した課題または Wiki の添付ファイル一覧に対応づけられること
3. 対応するファイル本体を、Backlog API を通じて正常に取得できたこと

変換先はアーカイブ内の相対パスだけにします。同一の添付ファイル ID は一度だけ保存し、本文ごとの変換表から参照します。課題添付ファイルは課題取得 API から一覧を得ます。Wiki 添付ファイルは Wiki 本体の応答を使い、本文参照に不足がある場合だけ専用の添付一覧 API で補います。本体はいずれも専用のダウンロード操作で取得します。

## 取得しない画像

次の画像は初期版で取得しません。

- 外部サイトの URL を参照する画像
- 同一 Backlog スペースであっても、指定プロジェクトの添付ファイルとして確認できない画像
- 他プロジェクトの課題・Wiki・共有ファイルに属する画像
- `data:` URL など、添付ファイルに対応づけられない埋め込みデータ
- URL はあるものの、添付ファイル ID または取得対象との対応を確認できない画像
- `![Alt][label]` 形式で、添付メタデータとの一致も `[label]: URL` 定義もない画像参照

外部 URL や対象外の画像を `<img>` 要素や CSS の URL として生成 HTML に残しません。これにより、`file://` で開いたときに画像の表示をきっかけとする外部通信は発生しません。

## 取得失敗と表示

対象の添付ファイルであっても、権限不足、削除、ネットワークエラーなどで本体を取得できない場合があります。本文は削除せず、画像位置には「画像を取得できませんでした」と理由区分を示すプレースホルダーを表示します。

取得記録には、元の課題または Wiki、添付ファイル ID、失敗区分、取得日時を残します。認証情報、API キー、応答本文、URL のクエリやフラグメントは記録・表示しません。

## 将来の拡張

外部画像や対象外プロジェクトの画像を取得する必要が生じた場合は、利用者が明示的に許可する取得範囲、アクセス制御、保存先、失敗時の扱いを別機能として設計します。初期版のアーカイブ作成では自動取得しません。
